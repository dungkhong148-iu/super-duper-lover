LAYOUT (top to bottom; Vietnamese text; all single-line labels via OneLineText)
 1. Top bar: ✕ (Close, contentDescription "Đóng") left, title "Thêm giao dịch" / "Sửa giao dịch", ✓ (Check, "Lưu") right.
    ✕ closes without saving. ✓ evaluates the expression first (step 7) and then runs the same save logic as today (validateTxn, then repo.saveTxn).
    Build it with a Row like ChiLiTopBar does (ChiLiTopBar has a back arrow, not ✕; do not change it). Scaffold already pads system bars.
 2. Type tabs: three equal-width tabs "Chi tiêu" · "Thu nhập" · "Chuyển khoản", full width, one line each (OneLineText), each with its colour
    (TxnKind.color()) and icon (TxnKind.icon()); selected = tinted container + 2dp border + semantics selected. Min height 48dp.
 3. Amount header: a rounded 16dp box tinted with the type colour at ~16% alpha (container tone, not full saturation):
    sign ("-" expense, "+" income, none for transfer) + amount in displayMedium, ONE line, auto-size (OneLineText) + currency symbol is part of formatMoney.
    Under the number, when the typed text has an operator, the expression itself in bodyMedium muted (e.g. `50k+30k`).
    Shown value: no operator -> formatMoney(parseAmount(expr) ?: 0, currency); operator -> formatMoney(evalAmountExpr(expr, currency) ?: 0, currency).
    Amount errors (errorsAbout("số tiền")) go right under the header in the error colour.
 4. Pickers row (two equal buttons, outlined, min height 56dp, label above value, value one line): "Tài khoản" | "Danh mục"
    (transfer: "Từ tài khoản" | "Đến tài khoản"). Tap opens a ModalBottomSheet list (AddPickers.kt):
      - account sheet: one row per account (non-archived, plus the selected one if archived): name, currency code, type icon is optional; selected row checked.
      - category sheet: grid or list of categories of the type (sorted by usage like today), icon + name, selected checked.
    Account errors under the row, category errors under the category picker.
 5. (not for transfer) One horizontal row of chips: the 8 most used categories of the type (usage order) + a final chip "Tất cả" that opens the
    category sheet. Selecting a chip sets the category (chip selected state visible). Chips min height 48dp... use FilterChip.
 6. Compact row: date chip (OutlinedButton showing "Hôm nay" or the date; opens the same DatePickerDialog as today) + note field (OutlinedTextField "Ghi chú", single line, weight 1f).
 7. Cross-currency transfer only: below the pickers a field "Số tiền nhận (symbol)" exactly like today (OutlinedTextField, parseAmount with the TARGET account's currency).
 8. Number pad fixed at the bottom, above the system bar: 4 columns. Columns 1-3 digits:  7 8 9 / 4 5 6 / 1 2 3 / (000 or .) 0 ⌫.
    Column 4 operators: ÷ × − + and "=" (five keys over four rows: make the "=" key span the last two rows, or use rows of ÷ × / − + / = taller; your choice,
    but every key >= 56dp tall and >= 48dp wide, 6dp gaps). "000" key becomes "." when the currency has decimals (USD) - same rule as today.
    Typing rules (state = one String `expr`):
      - digit: append (leading zero rule as today; at most 14 characters total; for a USD number at most 2 digits after the "." in the current operand).
      - "." (USD only): append only if the current operand has no "." yet; an empty operand gets "0.".
      - operator: append the symbol (use "+", "-", "*", "/" in the string); if the last character is already an operator replace it; ignore at the very start (an expression cannot start with an operator).
      - ⌫: remove the last character. Long-press ⌫ clears everything.
      - "=": if evalAmountExpr(expr, currency) != null, replace expr with amountToInput(result, currency); otherwise show the amount error "Biểu thức không hợp lệ" (do NOT clear).
    Keys' labels: show × ÷ − + (pretty), pass * / - + into the string. contentDescription for operators and ⌫ ("Chia", "Nhân", "Trừ", "Cộng", "Bằng", "Xóa số cuối").
 9. Save: amount = evalAmountExpr(expr, currency) (plain numbers go through it too; it handles groups and k). If null -> amount 0 so validateTxn reports "Số tiền phải lớn hơn 0".
    Everything else in `save()` stays as it is today (toAmount for cross-currency, categoryId rules, validateTxn, errors per field).
