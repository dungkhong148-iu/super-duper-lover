BACKUP FORMAT (version 1) - one JSON object. Amount-like and id fields are JSON integers (no ".", no exponent).
  {
    "app": "ChiLi",
    "version": 1,
    "exportedAt": "2026-11-08T10:30:00",
    "accounts":          [ {"id":1,"name":"Ví","type":"CASH","openingBalance":0,"archived":false} ],
    "categories":        [ {"id":1,"name":"Ăn uống","kind":"EXPENSE","icon":"food","archived":false} ],
    "txns":              [ {"id":1,"kind":"EXPENSE","amount":50000,"accountId":1,"toAccountId":null,"categoryId":1,"date":"2026-11-08","note":""} ],
    "budgets":           [ {"id":1,"month":"2026-11","accountId":null,"categoryId":null,"limit":1000000} ],
    "goals":             [ {"id":1,"name":"Du lịch","target":12000000,"deadline":"2027-04-30","archived":false} ],
    "goalContributions": [ {"id":1,"goalId":1,"amount":2000000,"date":"2026-11-08"} ]
  }
  Field names = the Kotlin property names of the entities in data/Entities.kt, except BudgetEntity.limitAmount which is
  written as "limit". Nullable fields are written as JSON null. Strings are escaped by org.json.

THE TREE (shared contract between PART 1 and PART 2)
  A parsed JSON value is: Map<String, Any?> (object), List<Any?> (array), String, Boolean, null, or a number that is
  Int, Long (= a JSON integer) or Double / Float / anything else (= NOT an integer, e.g. 12.5, 1e3, 12.0).
  A JSON string like "50000" is a String, never a number.

PART 2 - app/data

    SELECT * FROM categories ORDER BY id          -> allCategories(): List<CategoryEntity>
    SELECT * FROM txns ORDER BY id                -> allTxns(): List<TxnEntity>
    SELECT * FROM budgets ORDER BY id             -> allBudgets(): List<BudgetEntity>

    DELETE FROM accounts / categories / txns / budgets / goals / goal_contributions   -> clearAccounts(), clearCategories(),
      clearTxns(), clearBudgets(), clearGoals(), clearContributions()
    Bulk restore reuses the existing @Upsert functions (upsertAccount etc.): the ids in the entities are non-zero, so the
    rows keep their ids (SQLite AUTOINCREMENT moves its counter past the highest id).
  BackupJson.kt (data package; the only file that uses org.json):
    class BackupData(val accounts: List<AccountEntity>, val categories: List<CategoryEntity>, val txns: List<TxnEntity>,
                     val budgets: List<BudgetEntity>, val goals: List<GoalEntity>, val contributions: List<ContributionEntity>)
    fun BackupData.toJson(exportedAt: String): String
        build with org.json.JSONObject / JSONArray; JSONObject.NULL for null fields; numbers put as Long (never Double);
        "app":"ChiLi", "version": BACKUP_VERSION; toString(2) is fine.
    fun jsonToTree(json: String): Map<String, Any?>
        strip a leading BOM (\uFEFF); parse with org.json.JSONObject(text) (a JSONException or a top level that is not an
        object -> throw IllegalArgumentException("Tệp không phải JSON hợp lệ")). Then convert recursively and WITHOUT changing
        number types: JSONObject -> LinkedHashMap<String, Any?> (via keys()), JSONArray -> ArrayList<Any?>,
        JSONObject.NULL -> null, everything else (Int, Long, Double, String, Boolean) unchanged.
        (org.json ignores text after the closing brace; that is accepted.)
    fun validateBackupJson(json: String): List<String>
        try { jsonToTree(json) } catch (e: IllegalArgumentException) { return listOf("Tệp không phải JSON hợp lệ") },
        then return validateBackup(tree) from :core.
    fun parseBackup(root: Map<String, Any?>): BackupData
        maps the (already validated) tree to entities: (row["amount"] as Number).toLong(), nullable ids via
        (row["toAccountId"] as Number?)?.toLong(), strings via `as String`, booleans via `as Boolean`; "limit" -> limitAmount.
        May throw (ClassCastException, NullPointerException); the caller catches.
  Repo.kt - add exactly these two methods (they use `db.withTransaction`, already imported):
    suspend fun exportBackupJson(): String
        reads the six tables with the new DAO queries INSIDE one db.withTransaction (consistent snapshot) and returns
        BackupData(...).toJson(exportedAt = LocalDateTime.now().withNano(0).toString()).
    suspend fun importBackupJson(json: String): List<String>
        1) val errors = validateBackupJson(json); if not empty return errors (nothing touched).
        2) val data = try { parseBackup(jsonToTree(json)) } catch (e: Exception) { return listOf("Tệp sao lưu bị lỗi: ${e.message}") }
           - parse EVERYTHING before touching the database.
        3) db.withTransaction { clear the six tables, then upsert every entity from the file }.
        4) return emptyList(). If step 3 throws, Room rolls the transaction back (old data stays); let the exception
           propagate to the caller.
        A txn/budget that points to an account or category id missing from the file is still imported as is
        (the app has no foreign keys); do not add extra checks beyond validateBackup.

  - Button "Xuất dữ liệu": rememberLauncherForActivityResult(ActivityResultContracts.CreateDocument("application/json"))
    launched with the suggested name "chili-backup-yyyyMMdd.json" (today's date digits built from LocalDate). In the callback
    (uri non-null): scope.launch(Dispatchers.IO) { val json = repo.exportBackupJson();
    context.contentResolver.openOutputStream(uri, "wt")!!.use { it.write(json.toByteArray(Charsets.UTF_8)) } } then set the
    status message "Đã xuất dữ liệu" (or "Xuất thất bại: <message>" in a try/catch). uri null (cancelled) -> do nothing.
  - Button "Nhập dữ liệu": launcher ActivityResultContracts.OpenDocument() launched with arrayOf("application/json", "text/plain").
    Callback (uri non-null): read the file as UTF-8 text on Dispatchers.IO, then call validateBackupJson(text) (data package).
    If errors: show them in the error colour (one line each, max 5) and do not continue. If valid: keep the text in state and
    show an AlertDialog: title "Thay thế toàn bộ dữ liệu?", text "Dữ liệu hiện tại sẽ bị xóa và thay bằng nội dung tệp. Không
    thể hoàn tác.", confirm "Thay thế", dismiss "Hủy". On confirm: errors = repo.importBackupJson(text) on a coroutine; empty ->
    message "Đã nhập dữ liệu"; otherwise show the errors; catch exceptions -> "Nhập thất bại: <message>".
  - A status Text under the buttons. Disable both buttons while an operation runs.
  - Buttons: full width, min height 48.dp. State with remember { mutableStateOf(...) }. No ViewModel, no new library.
